# 044: 工期最小端の欠けは作業リストの問題（再現はできる）— 優先規則シードで解消。max_shift の段差は連鎖で起きる

## 発生日
2026-10-02（10/1 ゼミの指摘1・2・4・5への対応）

## 指摘1: j309_1 RR050_RV0 で3手法とも工期最小端が 159 止まり（MIP は 125）
- **再現はできる**: MIP の工期最小解（125）は MaxShiftDur で全30活動を再現できる。
  しかも同じ作業順なら窓幅を全部0にしても 125 になる → max_shift ではなく**作業リストの問題**。
- ランダム作業リスト3,000個の最良 159、単目的GA(A2, 10万評価×5) 139、挿入局所探索 139、
  FBI（前向き後ろ向き改善, 時間変動容量対応）139/159、LFT 優先の偏りランダム生成 139（2秒）。
  どれも 125 には届かない。125 の解は大きな作業のかたまり（作業13・19・20）の順序がまるごと違う＝1作業ずつ動かす探索では届かない。
- **対策（効いた）**: LFT 優先の偏りランダム生成（重み (優先度差+1)^3、2000本→上位12本）で作った作業リストを
  `--a2seed 12 --seed-dir=results/EXT_COST/SEED_PR` で初期集団に入れる（`tools/ext1001/gen_pr_pool.py`）。
  - j309_1 RR050_RV0: 159 → **125（MIP と一致）**。作業リスト集単体の最良は 139 だったが、NSGA の交叉で 125 に到達した。
  - MIP がある240条件: 工期最小端が MIP と一致 190 → **211**、MIP より10%以上長い 10 → **3**。
  - 前線全体の共通HV: +0.0014（SE 0.0012）＝悪化なし（ノイズ rp1−base は −0.0002, SE 0.0007）。
  - 8月の A1（優先規則シード）は前線全体の平均だけで評価して不採用にしていた。端点の欠けという具体的な対象で測ると効果ははっきり出る。
- `--seed-dir` を NSGAMaxShiftDurCpp に追加（既定 results/FUN_A2 で従来どおり）。

## 指摘2・4: 再現できない具体的なケース（`tools/ext1001/repro_cases.py` → repro_cases_*.csv）
- 再現できる割合は前線の位置で大きく違う: 工期最小端 99% → 98% → 95% → 80% → コスト最小端 48%。
  **再現できないのはコスト最小端に集中**。工期側の欠けは再現性の問題ではない。
- 原因A（窓幅の上限 T/2 不足）: 1,283 活動。不足は中央値 18、最大 204 スロット。地平線の短い RV0 ほど多い。
- 原因B（手前に同じか安い時刻）: 127 活動。同コストのタイ 30、MIP が高い方を選んだ 97（差は最大 34.5）。
- 理論上限（窓幅無制限）: 拡張前 86.1%（同じ42インスタンス）→ 拡張後 97.8%。

## 指摘5: max_shift を変えると急にメイクスパンが増える理由（`tools/ext1001/sweep_events.py`）
- 4インスタンス・配置の変化 13,896 回のうち、メイクスパン増加は 5,144 回。
- **動かした作業自身が最後の作業になったのは 9% だけ**。91% は連鎖（中央値6〜7作業が押し出される）。
- 動かした作業自身の節約は合計 −1,043,656、押し出された作業のコスト増は +632,886 → **節約の61%が打ち消される**。
  先生の「1作業ではガクッと下がるが全体では微妙」の正体。
- 余裕時間（直前配置での次の後続開始まで）を超える動きだと、メイクスパン増加 63%・連鎖 91%。範囲内なら 19%・49%（資源による連鎖が残る）。
- 探索への示唆: 窓幅を作業の余裕時間と結びつける／配置が変わるのは「窓に初めて安い時刻が入った瞬間」だけなので、遺伝子を変化点の番号にする。
