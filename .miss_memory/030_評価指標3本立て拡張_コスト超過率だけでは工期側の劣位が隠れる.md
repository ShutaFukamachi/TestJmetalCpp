# 030: 評価指標を3本立て（工期ギャップ・HV・C-metric）に拡張 — コスト超過率だけでは工期側の劣位が隠れていた

## 発見日
2026-08-12（[[028]][[029]]の48インスタンスgap分析を、matched-cost makespan gap / Hypervolume比 /
C-metric に拡張する検証タスクで発覚）

## 背景
既存の matched-makespan gap（MIPの各点(m,c_MIP)に対しNSGAでms<=mの最小costを比較）は、
**NSGAがそのmakespan mに到達できない場合、そのMIP点を静かにunmatchedとして落として集計から除外**
していた。実測すると 240/11,019点(2.2%)・197/828行(24%)がこれに該当し、SchedObj>MaxShiftDur>MaxShift
の順で該当行が多かった。「コスト側は測っているが工期側の劣位が数値に出ない」構造的な死角がある
と分かり、対称指標(工期超過率)とフロント全体を1値で見るHV、卒研で使用実績のあるC-metricを追加した。

## 実装
`tools/gap48_analysis.py` に3指標を追加（既存の matched-makespan gap 列は変更なし）:
- `ms_gap_mean/max, ms_unmatched_points` — 工期超過率（matched-cost makespan gap）。
  costをmatchさせてNSGAの最小msを比較。`min_ms_at_or_below_cost()`で計算（フロントがms昇順・
  cost非増加なので、cost<=cを満たす最初の点のmsが答え、という単純なO(n)走査で求まる）。
- `hv_mip, hv_nsga, hv_ratio` — Hypervolume。(instance,condition)ごとにMIP∪NSGAの全有効点の
  min/maxで両目的を[0,1]正規化し、共通nadir=(1.1,1.1)で計算。系列ごとに別々の参照点を使うと
  比較が無意味になる点に注意（今回は正規化を(instance,condition,method)単位＝行ごとに行った
  ため、union_ptsに含まれるのはMIPとその1手法のみ。手法間で正規化スケールが微妙に異なりうるが、
  hv_ratio自体は同一行内でMIP/NSGAが同じスケールを使うため比率としては有効）。
- `c_mip_over_nsga, c_nsga_over_mip` — C-metric（弱支配ベース、`<=,<=`）。

## 主な発見

### ① 工期側のgapはコスト側の10〜20倍大きい（絶対値として）
matched-cost makespan gap（工期超過率）の平均: MaxShiftDur 7.13%、MaxShift 7.42%、
SchedObj 14.88%。既存のmatched-makespan gap（コスト超過率）が0.5%前後だったのと比べ、
**桁が一つ違う**。工期方向のunmatched率も点ベースで12.7%(MaxShiftDur)〜22.4%(SchedObj)と、
コスト方向(1.4〜3.1%)よりずっと高い。→ **NSGAのフロントはMIPに比べて「安いが遅い」領域への
到達性が構造的に弱い**。これは既存指標では見えていなかった。

### ② 手法の序列はどの指標でも変わらない（MaxShiftが逆転する兆候は無かった）
コスト超過率・工期超過率・HV比のいずれでも **MaxShiftDur < MaxShift ≪ SchedObj**
（HVは大小逆で MaxShiftDur > MaxShift ≫ SchedObj）の順が一貫した。事前の懸念（MaxShiftが
工期到達性で有利な可能性）は実測では支持されず、むしろ工期方向のunmatched点比率も
MaxShiftDur(12.7%) < MaxShift(14.9%) と MaxShiftDur が上回った。**結論は指標を変えても揺らがない**。

### ③ HV比はコスト側とms側の中間的な値になり、両方の情報を統合している
HV比のシェアフォール（1-hv_ratio）中央値: MaxShiftDur約1%、MaxShift約2%、SchedObj約9%。
コスト超過率(0.5%/0.5%/1.5%)より大きく、工期超過率(7%/7%/15%)より小さい —
**2目的分の乖離を1値に畳み込んだ結果として妥当な中間値**になっている。ただし RR=0.50 条件で
HV比の分散が非常に大きくなる（std 0.22〜0.28、max 1.2〜1.3超）ケースがあり、これは
MIPフロントが1〜2点しかない縮退ケース（[[028]]で既出）でHVが不安定になるため。**フロントが
極端に小さい行はHV比を単独で解釈せず、mip_pf_size/nsga_pf_sizeと併読すること**。

### ④ C-metricは前線の密度差に弱く、絶対値をそのまま「品質」と読んではいけない
C(MIP,NSGA)（NSGAの点がMIPに弱支配される割合）は MaxShiftDur/MaxShift で約59〜60%、
SchedObj で約85%と、一見「NSGAの4割が悪い」ように見える数値になった。しかし内訳を見ると、
**MIP側のフロントは疎（εブレイクポイント30点サンプリングで7〜30点程度）、NSGA側は密
（最大400点）**であるため、NSGAが見つけた中間的な良い点がMIPの疎な格子点のどれからも
弱支配されない、という前線密度差由来のアーティファクトが相当量含まれる。序列
（MaxShiftDur≈MaxShift < SchedObj）自体はコスト・工期・HVと整合するので比較には使えるが、
**絶対値（%）はそのまま「不良解の割合」と解釈しない**こと。C(NSGA,MIP)（MIPがNSGAに弱支配
される割合）は全手法で0〜6%と低く、既存の`dominated_points`（厳密支配、4行のみ）と整合する
（厳密支配ではなく同点タイでの弱支配が大半、[[029]]で既出のMIP ε-breakpoint疎さの帰結）。

## 結論・示唆
- 「提案手法は厳密解の0.5%以内」という既存の結論（[[028]][[029]]）は**コスト方向に限定した
  話**であり、工期方向を含めた総合評価（HV）では乖離がもう少し大きい（shortfall中央値
  約1〜2%）。ただしSchedObjとの相対的な優位性はどの指標でも揺るがない。
- 今後「差を詰める」対象を選ぶなら、コスト側の微調整よりも**工期方向の到達性（安いが遅い領域の
  探索）**を優先する方が実質的な改善につながる可能性が高い。ただしこれは絶対値の話であり、
  厳密解ソルバー(MIP)自体が疎なεブレイクポイントで「安いが遅い」領域を粗くしか探索していない
  （[[026]][[027]]）ため、工期側の見かけ上の差の一部はMIP側の粒度に起因する可能性も残る
  （切り分けは未実施）。

## やらなかったこと・今後
- HVの正規化を(instance,condition,method)単位ではなく(instance,condition)単位に統一する
  （3手法+MIPの4系列全体の和集合でmin/maxを取る）検討はしていない。今回は行ごとの
  hv_ratio比較としては問題ないが、hv_mip自体を手法間で横比較する用途には使えない点に注意。
- 工期側の「安いが遅い」領域でNSGAが弱い根本原因（探索が届いていないのか、そもそも
  そのような解を生成する余地が少ないのか）の切り分けは未実施。
