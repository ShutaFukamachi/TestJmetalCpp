# 038: D4WindowRank（窓幅・コスト順位計測ツール）新規作成 — [[024]]のコスト表クランプ問題の実害を定量化

## 発生日
2026-09-10（ゼミ指摘1・2対応の計測ツール新規作成タスク）

## 作ったもの
新規ターゲット `D4WindowRank`（`main_D4_WindowRank.cpp`）。`results/FUN_MIP/<inst>/
SCHED_MIP_*.txt`（読み取り専用）を直接パースし、MIPの各活動の開始時刻 s*_j に対して:
- **rank**（コスト順位）: `[t_mak, s*_j]` 内で s*_j より安い/同コストで早い候補が何個あるか
  （`n_cheaper`, `n_tie_earlier` を明示的にカウントし `rank = 1 + n_cheaper + n_tie_earlier`）
- **rho_needed**（窓充足診断）: `RCPSP_Problem_MaxShiftDur.cpp` と同一の
  `eff_j = max(alpha*d_j, beta*T)` を使い `rho_needed = w_needed / eff_j`
  （>1.0 ならその窓設定では原理的に到達不能）
を1ジョブ1行で `results/ANALYSIS_D4/D4_<inst>_<cond>.csv` に出力する。
`main_D2_Reproducibility.cpp::runTestA` の強制配置・自然順序という考え方をベースに、
デコーダのロジック（canPlace/computeJobCostAt/getAlpha/getBeta）は public アクセサ経由で
「呼ぶだけ」、デコーダ本体・MIPは一切変更していない。D2Repro自体も変更していない。

## 実装時の注意点（教訓）
1. **クロス検証を追加した**: SCHED_MIP ファイルのヘッダ（duration/demand/capacity/
   capacity_t）と `.sm` から再構築した `RCPSP_Problem_MaxShiftDur` の値が一致するかを
   起動時に必ず照合し、不一致なら測定せず中断する（[[017]]の「系列間コスト表・容量
   プロファイル不一致」の再発を機械的に防ぐ）。
2. **コンソール出力は英語で統一すること**: 日本語文字列リテラルを `cout`/`cerr` に
   直接書いたところ、`/execution-charset:SHIFT_JIS`（プロジェクト全体のコンパイルオプション）
   と実行時のターミナルのコードページ不一致で **文字化けが実際に発生した**
   （警告 C4566 `ユニバーサル文字名...現在のコードページ(932)で表示できません` も出る）。
   既存ツール（D2Repro, main_MIP_RCPSP.cpp 等）は元々 cout/cerr を全て英語にしていた
   のはこのため。**新規ツールのコンソール出力は日本語を使わず英語で書く**こと
   （コメントは日本語で問題ない。コンパイルされないため）。

## 重要な発見: [[024]]「コスト表 horizon(165) < スケジュール horizon(RV1で597)」の実害を定量化
D4 に「コスト表クランプ診断」を追加実装（`readCostTableHorizon()`でCSVヘッダのみ読む、
読み取り専用）。j309_1 RR000_RV1 で実測:
- コスト表 T_cost=165、スケジュール T=597（3.6倍）
- `s_star >= 165`（クランプ影響区間）: **93/330 job-rows = 28.2%**
- rank>=2（非rank1）だった32件は**全てcost_diff=0.00**（n_cheaperは1件も無く、
  全てn_tie_earlier由来）。クランプ区間だけでなく非クランプ区間でも同傾向。

これは [[024]] が「要修正」と書きながら未対応のまま残っていた設計欠陥が、
**t>=165のジョブでコストが完全に定数化する**という形で実際にデータへ影響している
ことを初めて定量的に示した。RV=1条件（休暇日ありでhorizonが3.5倍に伸びる)ほど
影響が大きい（j309_1 RR050_RV1では `--all` 実行で fully-reproducible fronts が
0/7=0%まで悪化、他のRV0条件は50-100%）。

## 教訓
- **「タイが多い」という測定結果を見たら、まず測定対象のデータ自体に既知の欠陥がないか
  疑うこと**（[[016]][[017]][[024]]と同じ反射）。今回は真にタイ(同コスト)なのか、
  コスト表クランプによる「見せかけのタイ」なのかを区別する診断（コスト表T vs
  スケジュールT、s_star>=T_costの行数比率）を追加したことで、測定結果の解釈に
  必須の文脈を提供できた。
- 新規ツールで正本ファイル（`costs/costs_*.csv`, `results/FUN_MIP/`）を読む際は、
  読み取り専用アクセスであっても「そのファイルが実際に何を意味するか」（今回は
  ヘッダのT値がコスト表の定義域）を正しく理解した上で使うこと。
- 関連: [[016]][[017]][[025]]（MIP/コスト表の過去バグ系譜）、
  [[024]]（本タスクで実害を定量化した元の未解決課題）、
  [[031]][[035]]（公式結果ファイル誤上書き事故、今回は読み取り専用アクセスのみで実害なし、
  mtime diffで確認済み）。
