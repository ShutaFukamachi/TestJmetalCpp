# 027: MIP の ε 制約法が弱パレート最適解（同コストで makespan 最小でない）を返す → 辞書式2段階で解消

## 発生日
2026-08-04（[[026]] のブレイクポイント方式導入後、一部条件で NSGA が MIP を「支配」して見える事象への対応）

## 症状
`solveCost(eps)` は「makespan ≤ eps のもとで cost 最小化」のみを行うため、**コストが同じなら
makespan を縮める動機がない**。例:

| 条件 | NSGA (ms, cost) | MIP (ms, cost) | Δcost |
|---|---|---|---|
| j3047_1 RR075_RV1 | (274, 292419) | (277, 292419) | 0.00 |
| j3047_1 RR000_RV1 | (232, 271254) | (244, 271254) | 0.00 |

MIP は真のパレート最適でない弱パレート解（同コストでより大きい makespan）を返していた。
NSGA は2目的探索なので同コストで makespan が小さい解を自然に見つける。

## 原因
ε制約法（AUGMECON以前の素朴な版）の理論的弱点。目的関数がコストのみだと、実行可能領域内で
コストを変えずに他方の目的（makespan）を改善できる余地があっても最適化されない。
参考文献（Rodríguez-Ballesteros ら, ESWA 2026）が AUGMECON の `−γ·s` 項で回避しているのも同じ理由。

## 修正（辞書式2段階、AUGMECON相当）
`RCPSP_MIP_Solver::solvePareto()` の各 ε 点で:
- **Stage 1**（既存）: `min cost` s.t. `ms ≤ ε` → `C*` を得る。
- **Stage 2**（新規）: `min ms` s.t. `ms ≤ ε` **かつ** `cost ≤ C* + tol`（`tol = 1e-6*max(1,|C*|)`）
  → makespan を詰める。Stage2 不可解ならフォールバックで Stage1 の解を採用。

実装: `solveMakespanBounded()`（`RCPSP_MIP_Solver.cpp` 内 anonymous namespace の新関数）。
`Result` に `makespanBeforeTighten` を追加し、`GAP_MIP_*.csv` に列を追加して詰まった量を可視化。
`FUN_MIP_*.txt`/`SCHED_MIP_*.txt` は Stage2 の解（詰めた後の makespan・startTimes）を書く
（フォーマットは不変、値のみ更新）。

## 効果（実測）
- j3047_1 RR000_RV1: ε=244 で Stage1 は ms=244,cost=271254 → Stage2 で **ms=232 まで詰まる**
  （タスクの期待値と一致）。1条件（8ε点）の所要時間 29.5秒（Stage2 追加でほぼ倍だが依然高速）。
- 全40条件を辞書式2段階で再生成。`tools/verify_cost_consistency.py`: MIP **438/438** cost_ok・
  prec_ok（正本コスト表・制約とも完全一致）。
- **NSGA が MIP の点を厳密支配するケースが 40/40 条件でゼロ**になった（feasible な NSGA 点のみで
  比較。0/438 MIP点が支配された）。

## 副次発見1: 可視化サマリの ms*/cost* は「実点ではない」アーティファクト
`visualize_mip_comparison.py` の `stats()` は `ms* = min(全点のms)`、`cost* = min(全点のcost)` を
**独立に**計算しており、実在する1点の座標ではない。これにより j309_1 RR075_RV1 で
「MIP(457,311235) vs NSGA(457,310470)」という**存在しない点同士の比較**が生成され、
タスク開始時の「弱パレートでは説明できない Δcost=−765」という誤った所見の原因になった。
実際の MIP 前線点は (457, 322137)（Stage1のみ、最適性証明済み）であり、NSGA にも
ほぼ同一の実点 (457, 322137〜322199) が存在し、真のギャップはほぼゼロ。
- **教訓**: PF サマリで "ms* / cost*" を別々の列 min で出す表示は、実在しない仮想点を
  生み、手法比較の誤診断を招く。今後この種の表を見るときは「実在する1点の座標か、
  列ごとの独立最小値か」を必ず確認すること。

## 副次発見2: j309_1 RR075_RV1 の「NSGA が本当に安い」点は precedence 違反4〜5件の phantom
NSGA の実点最小コスト (557, 310470)（P1_MaxShift/MaxShiftDur 両方）を .sm の先行関係で検証したところ、
**前線中の全該当点が precedence violation 4〜5件**を含む実行不能解だった（[[018]] 「最適値を下回る
目的値＝実行不能の兆候」と同じパターン、[[024]] で既知の高RR/RV下での phantom 混入の再現）。
MIP はこの ms=557 で cost=311235（gap=0, 最適性証明済み）であり、真のパレートフロントは
MIP が正しい。
- **教訓**: 手法比較で「NSGA が MIP の証明済み最適を下回るコスト」を見たら、**まず NSGA 側の
  precedence/資源制約を検証**すること（`tools/verify_cost_consistency.py` は precedence のみ
  チェックし資源制約はチェックしないため、資源側は別途 capacity_t で検証が必要）。
