# 008: P1（作業分割なし）でパレート解が1個しか出ない原因と診断方法

## 発生日
2026-06-10

## バグの概要
P1（作業分割なし）で NSGA-II を実行すると、条件によってパレート解が1個しか得られない。
「探索が失敗しているのか」「真にパレート前沿が1点なのか」が不明だった。

## 根本原因の分析

### 原因A: P1 の資源制約が厳しく、実行可能スケジュールが限られる（問題の特性）

Serial Scheduling Scheme (SSS) では各ジョブを順に配置するが、P1 では分割なし（連続実行のみ）。
RCPSP の資源制約が厳しい場合、ジョブ j のコスト探索窓 `[t_mak, t_mak + maxShift]` 内に
実行可能スロットが `t_mak` しか存在しないことが多い。
このため `schedObj[j] = 1` に設定しても EST と同じ配置になり、
異なる解変数を持つ多数の個体が同一のスケジュール（＝同一目的関数値）に帰着する。
結果として、パレート前沿が genuinely 1 点しかない（問題固有の特性）。

### 原因B: SchedObj エンコーディングの maxShift が評価ごとに乱数変化（設計上の問題）

`RCPSP_Problem::buildMaxShiftForEval()` は静的な `rng(12345)` と `evalCounter_` を使い、
呼び出しごとに異なる maxShift ベクトルを生成する。
→ **同じ解変数でも評価タイミングによって異なる目的関数値** が返る（確率的目的関数）
→ NSGA-II のランキングが不安定になり、探索が収束しにくくなる。

MaxShift エンコーディングでは `vars[n..2n-1]` に max_shift を直接保持するため、
同じ解は常に同じ目的関数値を返す（決定論的）。これが SchedObj との差異の一因。

## 診断方法

`runStrategies()` に追加した診断ログ `[DIAG:...]` を確認する：

```
[DIAG:P1_SchedObj]  combined_valid=400  makespan=[30, 45]  cost=[1200.0, 3400.0]
```

| makespan 範囲 | cost 範囲 | 診断 |
|---|---|---|
| 広い | 広い | 探索は機能している。真に1点が支配的（問題の特性）|
| 狭い | 狭い | 探索が収束しすぎ（探索の失敗）|
| 広い | 狭い | makespan は探索できているが cost 方向が詰まっている |

## 教訓
- P1 の単解は「探索の失敗」ではなく「資源制約が厳しい問題インスタンスの特性」である可能性が高い
- SchedObj エンコーディングは maxShift が確率的であり、P1 の厳しい制約下では更に効果が薄れる
- P2/P3 では分割により実行可能スロットが増加し、コスト探索の余地が広がるため解が多様になる
- `[DIAG]` ログを常に確認し、「combined_valid が多いのに Pareto size = 1」なら問題特性と判断してよい
