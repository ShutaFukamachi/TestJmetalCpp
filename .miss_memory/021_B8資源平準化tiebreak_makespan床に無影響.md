# 021: B8 資源平準化 tie-break は makespan の床に無影響（neutral）

## 発生日
2026-07-22（A3/FBI 削除・E17 不採用の後、B/C 群の最初の実装として）

## やったこと
- `RCPSP_Problem_MaxShift` の evaluate 配置ループで、コスト同点の tie-break を
  「最早（左詰め）」→「残容量最大（資源平準化）」に切替える toggle を実装
  （`setResidualTieBreak`, default OFF）。A3AB ハーネスに B8 / A1+B8 条件を追加。

## データ（j309_1 RR050 RV0, 4戦略, 120k eval, 5試行）
| 条件 | best | mean | worst | minCost |
|---|---|---|---|---|
| OFF | 139 | 155 | 159 | ~413k |
| A1 | 139 | 139 | 139 | ~413k |
| **B8** | 139 | 155 | 159 | ~413k |
| **A1+B8** | 139 | 139 | 139 | ~413k |
→ B8 は OFF と、A1+B8 は A1 と **完全に同傾向**。makespan の床(139)を下げず、
  cost も悪化させない（FBI と違い neutral）。

## 根本原因（なぜ効かないか＝構造的理由）
- B8 の tie-break は **maxShift[j] > 0 の「コスト探索窓」内の同コスト候補**にしか作用しない。
  そこに現れるのは「コストのために遅延しているジョブ」であり、**クリティカルパス上の
  makespan 決定ジョブではない**。
- makespan の床を決めるのは各ジョブの **t_mak（最早実行可能時刻）配置**。t_mak は一意で
  選択の余地がない＝平準化しようがない。B8 はジョブを t_mak より前に置くことは決してできない。
- よって B8 は「後続の自由度を残す」つもりでも、実際には非クリティカルジョブを（同コストの）
  別スロットに動かすだけで、クリティカルパス＝makespan には触れられない。

## 教訓（次の意思決定に直結）
- **makespan の床は placement（配置）問題ではなく、順列/生成スキームの問題**。E17（配置は既に
  厳密最適の1.4%以内）と整合。tie-break や配置ヒューリスティックでは 139→125 は動かない。
- 効く可能性があるのは:
  1. **生成スキームの変更（Parallel SGS）**＝資源駆動で t_mak 構造そのものを変える（本命）。
  2. **C10 双方向シフト**＝非クリティカルを右詰めして早い資源を空け、クリティカルの t_mak を
     前倒しさせる（placement でなく到達可能スケジュールを変える）。
  3. 順列探索そのものの強化（構造的交叉 / D群の探索圧）。
- B8 コードは default OFF で残置（無害・負の結果の記録）。採用はしない。
- 安い実験で仮説を1つ潰せた＝良い投資。[[019]][[020]] と同じく best だけでなく mean/worst と
  cost floor の両方で判定した。
