# 011: 4戦略を std::async で並列実行する際のスレッド安全対策

## 実装日
2026-06-10

## 変更の概要
4つのストラテジーを逐次実行から `std::async(std::launch::async)` による並列実行に変更。
1ストラテジーあたり独立した `RCPSP_Problem` インスタンスを生成するファクトリ関数パターンを採用。

## スレッド安全の問題と対策

### 問題1: `static std::mt19937 rng(12345)` — データレース
- **修正**: `static thread_local std::mt19937 rng(std::random_device{}())`
- 各スレッドが独立した RNG を持つ。シードも `random_device` で独立させることで結果の多様性も確保。

### 問題2: グローバルコストテーブル (`COST_TABLE`, `COST_INITIALIZED`) — 初期化レース
複数スレッドが同時にコンストラクタを呼ぶと `COST_INITIALIZED = false` を競合してリセットし合う。
- **修正**: `std::atomic<bool> g_costInitialized` + `std::mutex g_costMutex` によるダブルチェックロック
- コンストラクタでのリセットは「別インスタンスへの切り替わり（CSV パスの変更）」時のみ実施
- `generateCostSeries()` 内で `lock_guard` + `g_costInitialized` チェック → 初回のみ生成

### 問題3: `static int sRunId`, `static bool sHeaderWritten` in NSGAII — データレース
- **修正**: `static thread_local int sRunId`, `static thread_local bool sHeaderWritten`
- 各スレッド（ストラテジー）が独立したランIDとヘッダフラグを持つ

### 問題4: 生成ログファイル競合 (`generation_log.csv`)
- **修正**: ストラテジーごとに `generation_log_s1.csv` ～ `generation_log_s4.csv` に分離
- `getStrategy()` getter を `RCPSP_Problem` に追加して stratId を取得

### 問題5: `std::cout` の混在出力
- **修正**: `EncUtil::syncPrint(msg)` — `std::mutex g_printMutex` でシリアライズ

## アーキテクチャ: ファクトリ関数パターン
```cpp
using ProbPair    = std::pair<RCPSP_Problem*, RCPSP_Problem_MaxShift*>;
using ProbFactory = std::function<ProbPair(int s)>;

// 呼び出し例
factory = [instFile, rr, rv, evals](int s) -> ProbPair {
    auto *p = new RCPSP_Problem_MaxShift(instFile, s, rr, rv);
    p->setMaxEvaluations(evals);
    return {p, p};
};
SolutionSet *pareto = runStrategies(factory, numStr, ...);
```
- `makeProb(s)` で strategy=s 専用の独立インスタンスを生成
- 返されたポインタは `runStrategies` 内のスレッドが `delete` する（所有権移譲）
- SchedObj では `{prob, nullptr}`、MaxShift では `{prob, prob}` を返す（同一ポインタで OK）

## 教訓
- `static` 変数を並列化する際は必ず `thread_local` か `mutex` を検討する
- コンストラクタでグローバル状態を無条件リセットするのは並列化と相性が悪い
- コストテーブルのような「同一インスタンスなら共有できる」状態は条件付きリセットにする
- `dynamic_cast<RCPSP_Problem*>(problem_)->getStrategy()` で NSGAII 側からストラテジーIDを取得できる
