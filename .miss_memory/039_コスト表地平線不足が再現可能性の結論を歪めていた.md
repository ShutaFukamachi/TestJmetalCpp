# 039: コスト表の地平線不足（[[024]]）が再現可能性の結論そのものを歪めていた

## 発生日
2026-09-10（D4WindowRank による大規模検証。[[038]]で単一インスタンス・単一条件で
見つけたコスト表クランプの実害を、46インスタンス×最大6条件へ横展開した結果）

## 背景
[[034]][[035]]では「argmin デコーダの理論上限は85.5%、残る14.5%は構造的制約
（貪欲デコーダの表現力限界）」という結論を出していた。D4WindowRank（[[038]]で新規作成）
でMIP厳密解に対する提案手法デコーダの再現可能性を大規模に検証したところ、
この結論自体が[[024]]で既に指摘されていた既知の未解決課題（コスト表の地平線不足）
によって歪められていたことが判明した。

## 症状（実測、46インスタンス×最大6条件=276条件、110,820ジョブ行）
- 再現不能（rank>=2、MIPの開始時刻より安い/同コストで早い候補がある）だった
  **2,531件**のうち、**2,022件（79.9%）がコスト表クランプ領域**
  （`s_star >= COST_T`）に該当していた。
- **コスト表が実在する領域（s_star < COST_T）に限ると、rank=1率は99.51%**
  （103,676行中）。
- j309_1は特にクランプ露出率が18〜37%と他インスタンスより突出して高く、これが
  「再現できない解がj309_1に集中している（全体の43.3%）」という現象の正体だった。

## 原因（[[024]]で既に特定されていたが未修正のまま残っていた設計欠陥）
`resourceCost()`（`src/problems/RCPSP_Problem.cpp:242`付近）:
```cpp
if (t >= COST_T) t = COST_T - 1;   // t をコスト表末尾にクランプ
```
コスト表は`costs/costs_<prefix>.csv`のヘッダで定義される固定の地平線
（例: j309_1で T=165）を持つ。一方スケジュールの地平線 T は容量プロファイル生成時の
factor（RV=1なら3.5倍）で決まり、例えばRV=1条件では T=597 に達する。
`t >= 165` の全ての時刻が同一のクランプ値を返すため、**その区間内のどの時刻に
活動を置いても「コストが完全に同じ」という人工的なタイが大量発生する**。
D2Repro/D4WindowRankのようなargmin再現性チェックは「同コストの候補が複数あれば
非決定的/構造的制約」と解釈するため、この人工的なタイを「デコーダの表現力の限界」
と誤って報告していた。

## 結論の訂正
- [[034]]の「貪欲デコーダの表現力限界」、[[035]]の「argmin理論上限85.5%」という
  結論は、**コスト表クランプという実装上の欠陥が生んだ見かけの限界**であり、
  デコーダのアルゴリズム自体の構造的限界を正しく測ったものではなかった。
- コスト表が実在する範囲でのみ評価すると、再現可能性はほぼ100%（99.51%）に達し、
  「探索の問題」でも「構造の問題」でもなく、**測定条件（コスト表の地平線とスケジュール
  地平線の不整合）の問題**だったことが分かる。
- [[040]]（同日作成、窓幅の実需に関する知見）とも整合する: 窓幅自体は十分に広く、
  正しい候補にほぼ確実に到達できる設計になっている。

## 教訓
- **問題設定のパラメータ（コスト表の定義域）と実験設定（スケジュール地平線）の不整合が、
  「手法の限界」という誤った結論を生むことがある**。手法の限界を主張する前に、
  その限界が実装・設定のartifactでないかを必ず層別して確認すること
  （今回は「s_star < COST_T」で層別しただけで結論が反転した）。
- **既知の未解決課題（[[024]]で「要修正」と記録されていたにも関わらず放置されていた）は、
  時間が経つほど別の調査結果を静かに汚染するリスクがある**。「要修正」と記録した課題は、
  優先度が低くても影響範囲を定期的に再確認すべきだった。
- 大規模検証（46インスタンス×276条件）でようやく可視化された偏り（j309_1への集中）は、
  少数インスタンスの予備調査だけでは見えなかった。[[028]]の「多インスタンス規模でないと
  見えない傾向がある」という教訓の再確認。
