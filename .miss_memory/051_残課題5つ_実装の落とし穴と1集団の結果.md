# 残課題5つ（2026-10-28〜29）: 実装の落とし穴と結果

## 実装の落とし穴（再発させない）
1. **コスト島で窓幅を全部最大にすると全個体が実行不能になる**
   - 窓幅を上限にすると作業が後ろへ押し出され、計画期間 T を越えて 1e9 になる。コスト島は
     「親の窓幅はそのまま、目標工期 D だけ制限なし（vars[n]=R）、λ=0」にした（costSideGenes）。
   - 教訓: 「端の個体を作る」ときに遺伝子を極端な値へ一括で振ると、実行可能性が崩れる。煙試験で best cost が出るか必ず見る。
2. **集団サイズを引数より前に読んでいた**
   - `populationSize = 100` を定数で初期化した後に `--pop` を解析していたので効かなかった。引数解析の後で代入する。
   - 教訓: 新しい引数を足したら、その値を使う変数がどこで初期化されているかを確認し、煙試験のログで実際の値を表示させる。
3. **P3Slot（MIP）を制限時間だけ変えて実行すると、120秒の結果を上書きする**
   - 出力名に制限時間が入っていなかった。`--tag=xxx` を足し、`FUN/GAP_MIP_P3SLOT_<p>_<cond>_xxx` に出す。
   - 教訓: MIP 側も NSGA と同じく、条件を変える実行は必ずタグで別名にする（公式結果を上書きしない）。
4. **P2/P3 の実行が探索オプションを受け取っていなかった**
   - main の P2/P3 経路は優先規則初期解・工期島・時間ブロック・目標工期のパラメータを NSGA-II に渡しておらず、
     「最終設定で P2/P3」と思っても中身は現在の手法だった。P1 と同じパラメータ群を渡すように直した。
   - 教訓: 設定を足すときは P1 経路だけでなく P2/P3 経路にも渡っているかを grep で確認する。

## 1集団（目標工期＋集団の中の工期島 ms-mate）の結果（課題4）
- j30: 工期端=MIP 228.0（dl 224.4、むしろ良い）、中間部 8.41%（dl 7.98%）、HV −0.0011±0.0011
- j120: HV −0.0042±0.0008（改善15/悪化105）、最良既知との差 5.31%（dl 5.10%）
- 不採用。工期側の子が集団の枠を取ると中間部と大きい問題例の前線全体が薄くなる。
  「端は集団の外（島）で探し、1体だけ送る」が枠を取らない分よい。10/23（matef0）、10/25（dl1p）と同じ向きで3回目。

## λ 遺伝子（課題1、休暇ありの中間部）の結果
- 診断では「休暇をまたぐ長い遅らせ（節約28/コマ）」が鎖を伸ばしていたが、配置を「コスト + λ×遅らせ」で選んでも
  鎖上の休暇またぎは 19.7 回のまま減らず、中間部は 7.98% → 9.38% に悪化（RV0 も悪化）。j120 の HV は +0.0085。
- 教訓: 「窓の中の選び方」を変えても、鎖の遅らせを決めているのは作業リストの順と窓幅の側。
  原因の場所（どの決定が鎖を伸ばすか）を診断で特定してから仕組みを足す。遺伝子を1つ足すと j30 では探索が薄まる。
- λ ありは1実行あたり約2倍遅かった（原因未確認）。時間を比べる前に必ず実測する（049）。

## コスト島（課題2）の結果
- コスト端 0.164% → 0.151%、HV 同等（j30 +0.0004、j120 +0.0004）、中間部 7.98% → 8.29%（基準 8.22% をわずかに超え不採用）。
- 親選び（dlc: 0.127% / 中間部 8.61% / HV −0.0020）よりは穏やか。「端は島で」の形は中間部への悪影響を小さくするが、ゼロにはしない。

## 集団50（課題5）と P2/P3 最終設定（課題3）の結果
- 評価 1/4 で集団50（世代数2倍）: j30 HV −0.0059（集団100 は −0.0086）、j120 +0.0097（96/120 で全評価の現在の手法を上回る）。
  教訓: 予算を減らすときは、世代数に比例して効く仕組み（島の停滞判定・変異）のために集団サイズも一緒に下げる。
- P2/P3 を最終設定に: MIP との HV 比が 30比較中28で上昇。P3 の MIP は 600秒でも最適性の証明 0/10（ギャップ 2.2→1.6%、2.8→1.5%）。
- HV 比が 1 を超えるのは MIP を工期の刻みでしか解いていないため。MIP の「最適」点を NSGA が下回ったら、まず許容誤差（0.004% など）を疑う。
