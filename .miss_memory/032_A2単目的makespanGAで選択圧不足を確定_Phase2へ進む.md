# 032: A2（単目的makespan GA）診断 — 選択圧不足が確定、Phase 2（シード注入）へ進む

## 発見日
2026-08-12（工期gap改善の切り分けタスク。[[031]]でA1が一般化しないと判明した後の
「初期化ではなく探索中の選択圧が原因か」を確定させる診断）

## 問い
純粋にmakespanだけを最小化するGAなら、MIPの工期に近づけるのか？

## 実装（新規ターゲット A2Makespan、新規オペレータは作らず既存を流用）
`main_A2_SingleObjMakespan.cpp`。設計の要点:
- `RCPSP_Problem_MaxShift` を **strategy=1** で構築するだけで、`getEffectiveHalfT()=0`
  により evaluate() 内で max_shift が必ず0にクリップされ、EST固定のデコードになる
  （クラス既存の仕様どおり、コード変更不要）。
- 交叉=MaxShiftCrossover、変異=MaxShiftMutation を**そのまま流用**（strategy=1では
  変異の第2段階＝max_shift変異が halfT_=0 のため自動的にno-op化される）。
- 新規実装は「makespanトーナメント選択＋(μ+λ)エリート打ち切り」の数十行のみ。
- 評価回数: 1 run = popSize100 × maxEvaluations100000（2目的ラン1ストラテジー分と同一予算）。
- マルチスタート R=10、8インスタンス×6条件で並列実行。**全体でわずか52秒**
  （2目的ランよりはるかに軽い。Pareto非支配ソート/混雑度計算が無いため）。

## 結果（8インスタンス×6条件、47件の有効比較）

| 指標 | A2（単目的） | 2目的NSGA（既存） |
|---|---|---|
| MIPのms\*に完全一致した件数 | **43/47（91.5%）** | 少数（本文参照） |
| 平均gap（best-ms基準） | **0.50%** | 2.71% |
| 最大gap | 11.2%（j309_1 RR050_RV0のみ） | 27.2%（同条件） |

**43/47件でMIPのms\*と完全一致**。唯一大きく届かなかったのは j309_1 RR050_RV0
（MIP=125, A2=139, gap 11.2%）で、これは既知の「makespan床139」問題そのもの
（[[019]]で真の最適125を確定済み、[[023]]でParallel SGSでは表現不能と判明済みの
active-but-not-non-delay解に相当すると推定される）。ただし2目的ラン(159)よりは
大幅に近い（159→139、A1の20/20試行と同じ床に到達）。

制約違反: `verify_precedence.py`のロジックを転用して全47解を検証、**違反0件**。
評価回数: 全480 run（8×6×10）で厳密に100,000（2目的と同一予算、確認済み）。

## 重要な副次的発見: j3034_1（工期gap最悪インスタンス）の正体
j3034_1は48インスタンス中もっとも `ms_gap_mean` が悪い（24.82%@RR050_RV0）ため
「A2で大きく改善するはず」と予想したが、**実際には2目的NSGAもA2もMIPのms\*に
6条件全てで完全一致した**（68/97/71/116/94/172、すべて一致）。
つまり j3034_1 の問題は「best-ms（フロント端点）に届かない」ことではない。
`gap_summary.csv` を確認すると、`mip_pf_size` が2〜15と非常に少なく（例:
RR050_RV0は6点、RR050_RV1は2点）、かつ多くのMIP点が `ms_unmatched` になっている
（NSGAのどの点もcost<=c_MIPを満たさない）。**端点は正しく捉えているが、
中間コスト帯でMIPほど密なフロントを作れていない**、という選択圧不足とは別種の
「フロントの密度・被覆」問題であると判明した。

## 切り分けの結論（1行）
**選択圧不足が確定（近づける側）。Phase 2（良い順列/解を2目的ランへ注入する）へ進む。**
ただし上記の j3034_1 の発見により、**Phase 2は「端点1個を注入する」だけでは
不十分な可能性が高い**。端点はどうせ2目的ランでも既に到達できていることが多く
（43/47件）、真に効くのは中間コスト帯を含む**複数の多様な良質解を注入する**か、
参照点付きNSGA-II等で**makespan方向の選択圧を全体に底上げする**アプローチだと
考えられる。単純な「A2のbest解を1個だけ注入」設計は、j3034_1のような
「端点は良いが中間が疎」なインスタンスには効果が薄いと予想される。

## Phase 2設計への示唆（次タスクへの申し送り）
1. j309_1のような「端点自体が2目的NSGAで届かない」インスタンスには、
   A2のbest解1個の注入が直接効くはず（[[031]]でA1が実際に効いたのと整合）。
2. j3034_1のような「端点は届くが中間が疎」インスタンスには、単一解の注入では
   不十分。A2をmakespanだけでなく**複数の異なるmakespan水準**でマルチスタート
   実行し、その集合を注入する（＝結果として広いmakespan帯をカバーする多様な
   良質順列の束を与える）方が筋が良い可能性がある。
3. Phase 2のA/Bでも[[031]]の教訓（単一インスタンスの成功を一般化しない、
   対照群でノイズ床を推定する）を必ず踏襲すること。

## 教訓
- **診断用の単目的ハーネスは、既存クラスの「strategy」パラメータを流用するだけで
  新規デコーダ実装なしに作れた**（RCPSP_Problem_MaxShiftのstrategy=1は元々
  「EST固定・makespan専用」の意味で設計されていたため）。既存コードの設計意図を
  読み解けば、新規実装は選択ロジックだけで済むことがある。
- **集約指標（ms_gap_mean）が悪いからといって、原因が同じとは限らない**。
  j309_1は「端点到達不足」、j3034_1は「フロント密度不足」と、表面上同じ
  「工期gapが大きい」でも根本原因が異なりうる。診断は集約指標だけでなく
  個別インスタンスの内訳（mip_pf_size, ms_unmatched_points等）まで見る必要がある。
