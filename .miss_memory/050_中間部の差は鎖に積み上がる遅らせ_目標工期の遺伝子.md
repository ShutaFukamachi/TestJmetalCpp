# 050: 前線中間部の工期差は「遅らせが工期の鎖に積み上がる」こと。目標工期の遺伝子（--deadline-gene）を追加

## 発生日
2026-10-24 夕方（残課題「前線中間部」と 10/1 指摘「max_shift をどう決めるか」）

## 診断（tools/ext1024/mid_delay_diag.py, mid_chain_diag.py、j30 全48×6条件、中間部 3,091組）
- MIP の中間点と、同じコスト以下で工期最小の NSGA 点（prtbw3 r1）を対にした。NSGA の工期は平均 +7.8%。
- 遅らせた作業の数・遅らせの合計・1コマあたりの節約は MIP とほぼ同じ（差の原因ではない）。
- 最後の作業から逆にたどった鎖で工期を分解: 中間部の工期 219 のうち 167 が鎖上の遅らせ。NSGA の +18 のうち +16 が鎖上の遅らせ。
- 復号し直しは MIP 97.1%、NSGA 100% が元の開始時刻を再現（開始順リスト＋窓幅=実際の遅らせ）。

## 追加したもの（既定 OFF）
- RCPSP_Problem_MaxShiftDur::setDeadlineGene: vars[n+0]（開始ダミーの窓幅、従来は未使用で常に0）を目標工期 D に使う。
  D = CP + (g/R)^2 (T − CP)。窓の右端を LST_j(D) = D − tail_j（先行関係だけの最長路）で打ち切る。
- setDeadlineOnly: 作業ごとの窓幅の遺伝子を使わず rho=1 にして、目標工期だけで窓を決める（探索的）。
- NSGAII: deadlineMutProb（目標工期の変異）、deadlineOnly（このとき「窓幅0」の子は目標工期を最小にして表す）。
  zeroWindows は j=0 の遺伝子を残すように変えた（従来は常に0で復号にも使わないので、既定の動作は変わらない）。
- ランナー: --deadline-gene, --deadline-mut p, --deadline-only（--cost-dir=costs_ext と --tag 必須）。
- 出力用の probOut にも同じ設定を入れること（入れないと SCHED の復号が変わる）。

## 注意
- 開始ダミーの遺伝子は、初期解（createRandomTopoSolution / 極端解）で 0 に固定され、MaxShiftDurMutation も j=1..n-2 しか動かさない。
  目標工期を使うときは初期化と専用の変異が必要（入れてある）。

## 結果（2026-10-24〜25、tools/ext1024/PREREG_20261024.md）
- 採用: dl（--deadline-gene --deadline-mut 0.2）。j30 中間部 8.66 → 7.98%（新しい r6〜r10 でも 7.96%）、j120 HV +0.0104。
  作業数ごとの HV（対 prtbw3）: j60 +0.0022、j90 +0.0048、j120（60×2回）+0.0047。計算時間は prtbw3 より短い（窓が打ち切られる）。
- 仕組み: 鎖上の遅らせは減らず、鎖の外への遅らせが増えて鎖の所要時間・資源待ちが減る形で効いた（予想と違う。そのまま報告する）。
- 不採用: --deadline-only（大きく悪化）、--deadline-cal（暦つき LST、2回の判定とも中間部で不合格）、dl + コスト側の親選択（中間部が薄くなる）。
- 判定基準を後から変えて再検証するときは、新しい実行だけで判定し、そのことを PREREG に明記する（dlcal の再検証でそうした）。
- 4並列（各4〜5スレッド）で CPU 使用率 87〜100%。夜通しは3並列。
- 働きの記録: RCPSP_Problem_MaxShiftDur::statWin_/statClamp_/statCut_（診断用）。ランナーは --deadline-gene のとき [DLSTAT] を出す。
  探索全体（j30 全48×6条件×4戦略、各1回、NSGA1025.exe の [DLSTAT]）で、窓を持つ作業の配置のうち 48.6% で目標工期が窓を打ち切り、打ち切られた幅は平均 74.6 コマ（休暇なし 50.4%・41.2 コマ、休暇あり 46.9%・108.3 コマ）。
