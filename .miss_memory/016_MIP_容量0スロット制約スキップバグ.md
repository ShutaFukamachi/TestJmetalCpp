# 016: MIP が容量 0 スロットの資源制約をスキップしていたバグ

## 発生日
2026-07-16

## 症状
MIPComparison 図で、RV=1 や高 RR 条件において MIP が NSGA-II (MaxShift) に
異常なほど大差を付けていた（makespan 差 +96〜+159）。

例: j3017_1 RR050_RV1
- MIP 申告値: makespan=213
- NSGA-II: makespan=372〜529
- 実行可能な Serial SGS の最良値（5000 ランダム順列）: 529

## 根本原因
`RCPSP_MIP_Solver.cpp` の資源制約構築ループ:

```cpp
int cap = prob.getCapacityAtTime(k, t);
if (cap <= 0) continue;   // ← バグ: 容量 0 の時刻は制約自体を張らない
```

RV=1 では 14 日ごとに全資源の容量が 0 になる（休暇日、rv_vacation_day_per_resource_bug.md 参照）。
容量 0 の時刻には「usage <= 0」という制約が必要なのに、制約自体をスキップしたため
**ジョブが休暇日を突っ切って実行できる緩和問題**を解いていた。

### 検証で得た証拠
- MIP の自己申告スケジュール (ms=213) を MIP 自身の出力 capacity_t で検証 → 資源制約違反 13 件
- 14/32 ジョブが容量 0 スロットを貫通して実行されていた
- capacity_t 自体は MIP と NSGA で完全一致（プロファイルは同一、モデル化だけが違った）

## 修正
容量 0 の時刻 t をカバーする開始時刻変数を禁止する（UB=0）:

```cpp
if (cap <= 0) {
    for (int j = 0; j < n; ++j) {
        int d = dur[j];
        if (d <= 0 || demand[j][k] <= 0) continue;
        int tau_lo = std::max(md->tStart[j], t - d + 1);
        int tau_hi = std::min(md->tEnd[j],   t);
        for (int tau = tau_lo; tau <= tau_hi; ++tau)
            md->xvars[j][tau - ts_j].set(GRB_DoubleAttr_UB, 0.0);
    }
    continue;
}
```

## 教訓
- **異なるソルバー（MIP vs メタヒューリスティック）を比較する前に、
  一方の解をもう一方の feasibility checker に必ず通すこと**（相互検証）。
- 「cap <= 0 なら制約不要」は誤り。容量 0 は「制約なし」ではなく「実行禁止」。
- 比較でどちらかが異常に強い場合、まず「同じ問題を解いているか」を疑う。

## 影響
- 修正前の MIP 結果（RV=1, 高 RR 条件）はすべて無効。
  旧結果は `results/FUN_MIP_backup_relaxed_20260716/` に退避済み。
- MIP を全インスタンス・全条件で再実行し、MIPComparison 図も再生成が必要。
- RV=0 かつ容量が 0 にならない条件の MIP 結果は影響なし（制約は元から正しい）。
