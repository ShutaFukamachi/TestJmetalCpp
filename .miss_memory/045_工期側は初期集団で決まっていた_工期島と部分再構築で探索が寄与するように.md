# 045: 工期最小端は「初期集団の最良」でほぼ決まっていた — 工期島＋部分再構築変異で探索が効くようにした

## 発生日
2026-10-14（10/14 ゼミ指摘「初期解に頼らず探索で解の質を高める」「仮説を立てて検証する」「初期解の分布を見る」）

## 追加したもの（すべて既定 OFF。OFF なら従来と同一動作）
- `RCPSP_Problem_MaxShift::sampleBiasedPriorityList(rule, alpha, rng, base, keep)`:
  優先規則＋ランダム性の作業リスト生成。重み (優先度 − eligible 内の最小 + 1)^alpha。
  rule 0=LFT 1=LST 2=MTS 3=GRPW、負なら4規則から一様。base/keep で「先頭 keep 個を残して後半を作り直す」。
- NSGAII の入力パラメータ: prInitFrac / prAlpha / regenProb / msIsland / msIslandKids / traceFile（std::string*）。
- NSGAMaxShiftDurCpp のオプション: `--pr-init f` `--pr-alpha a` `--regen p` `--island k` `--trace`。
  **拡張コスト表（--cost-dir=costs_ext）と --tag が無いと起動を拒否する**（公式結果に混ざらないように）。
- trace: `results/EXT_COST/TRACE/<prefix>/TRACE_<prefix>_<cond>_S<k>_<tag>.csv`
  init 行 = 初期個体（作り方, ms, cost, 窓幅0での ms）、gen 行 = 世代ごとの要約（最初50世代は毎世代、以降10世代ごと）。
- 解析: `tools/ext1014/`（run_variants.sh, eval_variants.py, trace_summary.py, search_contribution.py,
  init_alpha_sweep.py, plot_init_trace.py, eval_j120.py）。出力は analysis/ext1014/, figures/Init_EXT/。

## 仮説と結果（j30 全48インスタンス・276条件、MIP がある 240 条件。各1回実行、基準設定は3回でノイズを測った）
- 観察: 現在の手法では **最小メイクスパンが最後に改善した評価回数の中央値 = 100（初期集団）**。
  j30 で69%、j120 で29% の実行は初期集団の最良から一度も改善しない。工期最小端は初期解で決まっていた。
- H2「窓幅が良い作業リストを隠している」→ **棄却**。窓幅0で復号した方が短いのは記録の11.0%、
  逆に窓幅がある方が短いのも11.5%（時間変動容量では遅らせると後続が入りやすくなることがある）。
- H4「工期側にいる個体が少なく（100中12体、異なる作業リストは7本）、工期方向の探索がほとんど行われていない」→ 支持。
  対策「工期島」: 窓幅0に固定した作業リスト20本の小集団を、毎世代20個の子（予算の約17%）でメイクスパンだけを
  見て進化させ、最良が NSGA の集団に無ければ移民として加える。
- H3「挿入変異（1作業ずつ）ではかたまりの順序替えができない」→ 支持。対策「部分再構築変異」:
  子ごとに確率0.1で作業リストの先頭 k 個（k は一様）を残し、後半を優先規則＋ランダム性で作り直す。
- 初期集団の作業リストの分布: 優先規則＋ランダム性（a=3）は MIP 最小工期比の中央値 1.12 → 1.02。
  ただし **優先規則が悪い方向に偏る例がある**（j3037_1 RR025_RV0: ランダムの最良80、優先規則は全て96）。
  → 初期解を全部優先規則にしない（混ぜる）。

## j120（最初の10インスタンス × 6条件、各1回。基準は2回）
- RR000_RV0 は容量一定＝標準 RCPSP なので PSPLIB の最良既知値（tools/ext1014/psplib_j120hrs.txt）と比べた。
  j30 の最適値（psplib_j30opt.txt）は拡張 MIP の RR000_RV0 と 42/42 一致することを確認済み。
- 最良既知値との差: 現在の手法 9.9% / 10.4% → 部分再構築 5.8% → 工期島＋部分再構築 4.0% → 停止付き 4.4%。
- 共通 HV（基準2回の平均との差、ノイズ −0.0005）: 部分再構築 +0.0024、工期島＋部分再構築 **−0.0057**（悪化）、
  停止付き **+0.0020**（改善39/悪化21）。工期島は予算の約17%を使い続けるため、j120 ではコスト側が痩せる。
  **島が伸び悩んだら止めて予算を返す（--island-patience 30）と、工期の改善を保ったまま HV も悪化しない。**
- 推奨設定（現時点）: `--island 20 --regen 0.1 --island-patience 30`。ただし各1回・j120 は10インスタンスのみ。
- j120 でも工期島の改善は早めに止まる（最後に改善した評価回数の中央値 1,280〜2,720）。島の多様性の維持が次の課題。

## 副次的な発見: 初期集団の約3分の1が実行不能（罰則値 1e9）
- 窓幅0の作業リストだけなら RR000 では 0%。ランダムな大きな窓（最大 T/2）で作業が地平線 T を越えるのが原因。
  RR000_RV0 でも 35.8%。初期の評価の3分の1が無駄になっている（改善候補）。

## 注意
- 1回の実行で「届いた」を一般化しない: j309_1 RR050_RV0 は工期島＋部分再構築の試運転で 125（MIP と一致）に
  届いたが、本番の48インスタンス実行では 139。
- 実行中のシェルスクリプトを sed -i で書き換えたが、走っていたバッチは影響なし（sed -i は新しいファイルに置き換える）。
  それでも実行中のスクリプトは編集しない方が安全。
- `main_NSGAII_RCPSP_MaxShiftDur.cpp` は CRLF。Python で置換するときは改行コードをそろえる。
