# 事前登録（2026-10-24 夕方、実行前に固定）: 前線中間部と「max_shift をどう決めるか」

## 診断で分かったこと（tools/ext1024/mid_delay_diag.py, mid_chain_diag.py。j30 全48×6条件、中間部 3,091組）
- 同じコスト以下で比べると、NSGA（新しい最終設定 prtbw3）は MIP より工期が平均 7.8% 長い。
- 遅らせた作業の数（約26）、遅らせの合計（674 対 712 コマ）、遅らせ1コマあたりの節約は MIP とほぼ同じ。
- 工期を最後の作業から逆にたどった「鎖」に沿って分解すると、中間部の工期 219 コマのうち 167 コマは鎖上の作業の遅らせ。
  NSGA が長い 18 コマのうち 16 コマ（87%）が鎖上の遅らせの差。
- → 差は「どれだけ遅らせるか」ではなく「遅らせが工期の鎖に積み上がるかどうか」。MIP は工期の上限 ε の中で遅らせるので、
  遅らせは余裕のある作業に回る。今の復号は工期の目標を持たないので、各作業が窓の中で一番安い時刻を選び、鎖に積み上がる。

## 仮説 H-D と手法
- 各個体に目標工期 D を持たせ（vars[n+0]、D = CP + u^2 (T − CP)）、各作業の窓の右端を LST_j(D) = D − tail_j
  （先行関係だけで逆算した最遅開始）で打ち切る。窓幅は作業ごとの乱数ではなく、目標工期に対する余裕で決まる。
- 目標工期は子ごとに確率 0.2 で動かす（90% 正規分布 sd R/10、10% 一様）。初期解は一様乱数、コスト極端解は制限なし。
- 実行: dl = prtbw3 + --deadline-gene --deadline-mut 0.2（NSGA1024b.exe）。j30 全48 × 5回、j120（j1201〜j12020）× 3回。
- 事前確認（deadline_offline.py）: NSGA の既存解を目標工期で打ち切るだけで、43% の点で今の前線より安い（平均では悪い）。

## 採用の基準（prtbw3 と比べる。prtbw3 は既存の t1016_prtbw3_r1〜r5, j120 は r1〜r3）

- (m) j30 の工期端の一致数の5回平均 ≥ prtbw3 の5回の最小値（221）
- (n) HV 差（dl − prtbw3）の平均 + 2SE ≥ 0 を j30・j120 の両方で
- 3つとも満たせば採用。満たさなければ理由を診断で説明する（鎖上の遅らせが減ったか、など）。
- 仕組みの確認（記述のみ）: mid_chain_diag.py で dl の中間部の鎖上の遅らせが prtbw3 より減っているか。

## 探索的（基準なし、j30 × 3回、NSGA1024c.exe）
